## 7. Video implementation

* One `VideoBackground` component: `<video muted loop playsInline>` with **poster** frame first; plays only while on screen (IntersectionObserver), pauses off-screen.
* **Encoding:** 6–12 s seamless loops, no audio. Desktop 1920×1080 H.264 MP4 + VP9 WebM at about 2–4 MB; mobile 1280×720 or 960×540 at about 0.8–1.5 MB; WebP/AVIF poster. Done with ffmpeg in the build workspace.
* **Mobile & bandwidth:** below 768px only the hero (and the active tab's clip) load, as 720p; other bands show their poster. `prefers-reduced-motion` and Save-Data show posters only (play button available).
* **Readability:** per-section overlay gradient using NeuSix ink `#0F0F1F` (or a brand-accent tint), checked for WCAG AA contrast.
* **Focal point:** per-clip `object-position` so faces and subjects stay in frame on tall phone screens.
* No video sound, no autoplay outside the viewport, no parallax.

## 8. Responsive strategy

Mobile-first, fluid `clamp()` type and spacing (v1 system), CSS grid/flex. Specific adaptations: mega menu → full-screen accordion menu; split "tabs + video" sections → stacked (video on top, tab chips scroll horizontally); industry sticky split → stacked cards each with its own clip still; heroes use `svh` heights so mobile browser bars don't cause jumps. Tested at 320 / 375 / 430 / 768 / 1024 / 1280 / 1440 / 1920 for overflow, readability over video, tap targets and layout shift.
